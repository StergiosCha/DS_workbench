## Answers

### q1
REPRODUCED AND ROOT-CAUSED BY EXECUTION. Baseline: ds.parse('a man knows you','ttr') → ok=True; ds.parse('a man knows you .','ttr') → ok=False with ERROR 'Cannot parse: . — resetting' (emitted at src/dylan/parser/interactive_context_parser.py:584). The '.' word maps to template `assert` with PRED=A (src/dynamicsyntax/grammars/2015-english-ttr/lexicon.txt:611); the template (lexical-actions.txt:816-823) is: IF ty(t), complete, Speaker(X) THEN [IF (<Z>+Q || Assert(Y)) THEN abort ELSE put(Assert(X))] ELSE abort. Tracing each IF label on the completed tree (via p.complete_tree then lab.check_with_tuple_as_context): 'Ty(t)' → TypeLabel → True; 'complete' → GenericLabel → False; 'Speaker(X)' → GenericLabel → False. Cause: label_factory_create (src/dylan/tree/label/labels.py:665-735) has no case for the bare word 'complete' nor for 'Speaker(...)' — the unary-predicate whitelist regex is r'(?i)^(Tense|Class|person|Accept)\((.+)\)' (labels.py:26), so both fall through to GenericLabel (labels.py:570-590) whose check()/check_with_tuple_as_context() ALWAYS return False (labels.py:583-587). IfThenElse.exec_tuple_context (src/dylan/action/atomic/if_then_else.py:229-234) therefore fails at if_labels[1] ('complete', the first unsatisfiable condition; 'Speaker(X)' would fail next), takes the ELSE branch = abort for every left-adjustment permutation in _apply_all_permutations (interactive_context_parser.py:463-478), parse_goal returns False, parse_word resets and returns None (icp.py:583-587). Floor is NOT the problem: who_has_floor was already set to 'Dylan' by the previous word (icp.py:597) and no label consults it. NOTE: log_level='debug' is not a real level — LogLevel = Literal['off','error','warning'] (icp.py:37); 'debug' silently maps to a WARNING loguru sink (icp.py:181) and no stdlib branch (logging_config.py:56-62), so instrumentation is required (I used a scratch monkeypatch). MINIMAL SOUND FIX (verified working end-to-end via runtime patch, $TMPDIR/fix_proto.py): add two label classes to labels.py and two dispatch cases in label_factory_create: (1) CompleteLabel — check_with_tuple_as_context returns tree.is_complete() (Tree.is_complete exists at src/dylan/tree/tree.py:610), matched when s.lower()=='complete'; (2) SpeakerLabel modeled exactly on the existing AddresseeLabel (labels.py:402-443): parse 'Speaker(...)' with Formula.create(inner, True), check_with_tuple_as_context returns self._formula == AtomicFormula(context.get_current_speaker()) — Context.get_current_speaker() already exists (src/dylan/context/context.py:113-118, speaker of the top word on the DAG word stack, i.e. the word being parsed; metavariable X binds via MetaFormula equality just like AddresseeLabel). With this patch: 'a man knows you .' → ok=True with identical semantics to the period-free parse; 'a man arrives .', 'a man arrives ?', 'does a man arrive ?' all flip from False to True; existing tests still pass (tests/test_dynamicsyntax_parse.py: 30 passed). The THEN-branch inner disjunction '(<Z>+Q || Assert(Y))' stays a GenericLabel (labels.py:674-675 special-cases '||' to GenericLabel) → always False → routes to ELSE put(Assert(X)), which is the desired monologue behavior, so it needs no change for this fix (put parses 'Assert(X)' as an inert GenericLabel decoration). Scope caveat: accept/yes/reject templates (lexical-actions.txt:860-880) additionally use 'Assert(Y)'/'PrevSpeaker(Y)' which remain always-false GenericLabels — dialogue-act parsing needs further label classes beyond this minimal fix.
