### 2. computational-actions.txt — format and parsing (grammar.py)

Loader: `Grammar.__init__(dir)` → `_load_from_disk` (29-41): rejects URLs (32-34), errors-and-continues on missing file (36-38), runs `strip_block_comments` over all lines (39), then `_init_actions` (43-78).

Block format (verified against resources/2015-english-ttr/computational-actions.txt):
- Blocks separated by ≥1 blank line; first non-blank line of a block = RULE NAME (grammar.py:63-64); remaining lines = body handed verbatim to `ComputationalAction`.
- Name prefixes, stripped in order: `*` → `always_good=True` (non-optional star grammar; grammar.py:65-67), then `+` → `backtrack_on_success=True` (68-70). So `*+name` means both (file header comment, computational-actions.txt:4-7). `always_good` drives `DAGParser._separate_grammars` (dag_parser.py:47-56) into `nonoptional_grammar` vs `optional_grammar`; names `completion`/`merge`/`anticipation*` additionally go to `completion_grammar` (51-52). `+` is consumed only by induction code (hypothesiser.py:362,383).
- Body = one IF/THEN/ELSE (see §5). Examples: `intro-pred` (lines 11-22), `*thinning` `IF ?X / X THEN delete(?X)` (34-38), `completion` `IF ty(X) ¬?ty(X) </\\>Ex.x THEN go(/\\)` (40-45), `*elimination` with `ty(Y>X)` metavars (48-55), `trp` `IF complete THEN addaxiom` (184-187 area). `complete` is an unrecognized spec → `GenericLabel` (always False) unless handled elsewhere — check: it parses via label_factory_create fallback to GenericLabel; the trp rule fires only through... (in practice trp exists but `complete` never checks true; note as inert).
- Duplicate names silently overwrite (`self[name]=action`, grammar.py:88).

### 3. lexical-actions.txt / lexicon.txt / lexical-macros.txt (lexicon.py, effect_factory.py)

`Lexicon.__init__` (lexicon.py:182-249) orchestrates, in order: learnt-lexicon detection (`lexicon.lex-top-N.txt`/`lexicon-top-N.txt`, 204-219, 251-259; body format `[prob,rank]` line + word line + IF/THEN body, `_PROB_RANK_RE` line 172, loader 261-340), else: macros → `EffectFactory.init_macro_templates` (220-227), templates → `_init_lexical_templates` (228-232), words → recovery hook + `_read_words` (233-240), stats → `LexiconLoadStats` (241-249; dataclass 152-169).

lexical-actions.txt template format (`_init_lexical_templates`, 454-490):
- Blank-line-separated blocks. Header matches `_TEMPLATE_SPEC = (.+?)\\((.+)\\)` (line 17): `name(PARAM1,PARAM2,…)`, e.g. `proper(NAME,PERSON,CLASS)` (2015-english-ttr/lexical-actions.txt:10), `v_intran_fin(PRED,TENSE,PERSON)` (:486). A `*` prefix on the template name sets `no_left_adjustment=True` (479-481) → `LexicalAction.requires_left_adjustment()` False → parser applies it WITHOUT prior computational adjustment (icp:410-428 vs 430-478). Header not matching the regex raises ValueError (477).
- Body lines stored raw in `_LexicalTemplate` (734-756). Instantiation `create(word, metavals)` does positional plain `str.replace(param, value)` per line (747-756) → `LexicalAction(word, lines, template_name, no_left_adjustment)`.
- Bodies may call macros by name, including with substituted params: `event_restrictor(TENSE)` (:495) becomes `event_restrictor(pres)` after column substitution and resolves as an exact-name zero-arg macro.

lexicon.txt format (`_read_words`, 492-541): whitespace-split columns `word template_name arg1 … argN` (503-516); column count MUST equal template param count (`metavar_count` check 517-527, warning+skip otherwise); unknown template → debug+skip (510-514); instantiation errors → warning+skip (528-535). Columns bind POSITIONALLY: e.g. `john proper john s3 male` binds NAME=john, PERSON=s3, CLASS=male. Multiple rows per word append multiple LexicalActions (539); `lookup` truncates to `top_n` (362-365).

lexical-macros.txt (`EffectFactory.init_macro_templates`, effect_factory.py:66-105): same blank-line block structure; header via `_parse_macro_header` (23-36): `name(ARGS)` where params must ALL match `^[A-Z][A-Z0-9]*$` (33) — otherwise the WHOLE header (parens included) is the macro name with zero params (34-36; this is how `event_restrictor(past)` works). Bodies are effect lines. Expansion at parse time: `_create_lexical_macro` (126-150) — exact-name match first (132-135), else parse `base(args)`, check arity (144-147), substitute via str.replace (107-124), build `LexicalMacro` (atomic/lexical_macro.py:672-693) which runs sub-effects in order. Header comment warns: infix operators need brackets and spaces (lexical-macros.txt:1).

Recovery quirk: `_lexicon_recover_missing_templates` (801-819) + `_recover_template_from_raw_lines` (759-798) resurrect templates hidden inside `//* *//` blocks when lexicon.txt references them (e.g. deprecated `det_quant`, lexical-actions.txt:46-71 'this is now deprecated. No more epsilon terms').

### 5. IF/THEN/ELSE interpreter (q4) — if_then_else.py

Execution `exec_tuple_context` (206-246): top level resets ALL pooled metas + fresh `Backtracker` (216-221); nested levels reset only bound metas (221). Loop ≤64 attempts (225): check IF labels in order via `check_with_tuple_as_context` (Label default = pointed node, labels.py:103-105; ModalLabel = iterate all addresses reachable by the modality, TEMPORARILY repointing the tree, labels.py:516-529; NegatedLabel inverts, 562-564; ExistentialLabelConjunction all-parts, 393-394; AddresseeLabel consults dialogue context, 435-440). Pass→THEN, fail→ELSE (235); EMPTY branch → None (236-237); effects run sequentially mutating the tree, None short-circuits (238-242); on failure the `Backtracker` (47-101) unbinds the latest eligible meta (recording tried values), re-checks its IF label, resets later metas and reruns (245, 79-101); exhausted → None. Aborts propagate as None up through Action.exec → parser 'action inapplicable' (dag_parser.py:117-118; icp:420-422, 454-455) → DAG-level backtracking (`_adjust_once`, icp:342-365) → word-level reset/repair (icp:583-592). ### 8. Metavariable syntax summary

- Type metas in `ty(...)`: `[V-Z][0-9]*` → MetaType (dstype.py:18, 192-198). Grammar-file convention comment says 'Rule metavariables: X,Y,Z; Formula metavariables: A,B,C' (computational-actions.txt:8-9).
- Bare/requirement label metas (`?X` / `X` in thinning): `^(?:[V-Z][0-9]*|META)$` → MetaLabel (labels.py:27, 446-494, 686-733); separate pool from MetaType.
- `?x` / `Ex.x`: ArbitraryLabel ('any requirement' / 'any label', labels.py:167-168, 354-372, 685, 708-712).
- Formula metas for freshput: S,T,U only (fresh_put.py:355 regex).
- Modality metas: `<Z>` / bare uppercase → MetaModality (modality.py:21-31, 50-58); trigger-side binding NOT implemented (empty ops → relates only self).
- Modality syntax in triggers/effects: operators `\\/0 \\/1 \\/L \\/* /\\0 /\\1 /\\L /\\ \\/U` etc. (basic_operator OP_PATTERN), wrapped `<...>` (existential) or `[...]` (universal, `required=True`) (modality.py:9-59); modal labels `<mod>label` or `<mod>(a & b)` (labels.py:609-662); `¬` negation prefix (labels.py:677-680); `?` requirement prefix; `+feat` FeatureLabel; `!` BottomLabel; `Ex.` existential bundle; `(a || b)` disjunction NOT implemented → GenericLabel (labels.py:674-675).

## Gotchas
- Grammar is a dict subclass; duplicate rule names in computational-actions.txt silently overwrite (last wins) at grammar.py:88 — no warning. Same for duplicate lexical templates (lexicon.py:467,487) and macros (effect_factory.py:91,100).
- Missing computational-actions.txt only logs logger.error and yields an EMPTY grammar (grammar.py:36-38); the parser then runs with 0 rules and every parse just fails — no exception.
- Unrecognised effect lines become GenericEffect, a SILENT NO-OP that returns the tree unchanged (effect_factory.py:39-53, 263); unrecognised IF labels become GenericLabel whose check() is always False (labels.py:570-590). Typos in grammar files therefore fail silently, in two different directions.
- Block-commenting a lexical-action template with //* *// does NOT disable it if lexicon.txt still references it: _lexicon_recover_missing_templates re-parses the RAW file ignoring block-comment state and resurrects it (lexicon.py:801-819).
- Template parameter substitution is plain str.replace over each body line (lexicon.py:753-755) and macro expansion likewise (effect_factory.py:119-123): a parameter name that is a substring of another token or of a later parameter corrupts the body (e.g. a param named E would rewrite every letter E). Parameter names must be chosen to be substring-safe; there is no tokenization.
- Lexicon rows referencing a nonexistent template are only logger.DEBUG (lexicon.py:512) — invisible at default log level; arity mismatches at least get logger.warning (lexicon.py:518-524). Both are counted in LexiconLoadStats but that surfaces only via get_vocab()'s stats header.
- put() stores the LIVE meta-bearing Label object on the tree node (put.py exec uses self.label without instantiate); IfThenElse resets ALL pooled meta bindings at the start of every top-level action (if_then_else.py:217-218, reset_all_meta_bindings — deliberately stronger than Java per in-code comment), so any meta the label carries is retroactively unbound on the tree. Concrete DAG-edge copies come only from ComputationalAction.instantiate() (computational_action.py:43-54).
- Metavariable cells are POOLED GLOBALLY BY (class,name) (element.py:24-30): X in one rule is the same DSType cell as X in every other rule (but MetaLabel-X, MetaFormula-X, Modality-X are separate pools keyed by class). A schematic rule that leaves ?Ty(e>X) on a tree can later self-unify X := e>X, producing a CYCLIC binding and RecursionError in __str__ (observed empirically; dstype.py:142 <-> element.py:86 mutual recursion).
- MetaModality in an IF trigger never searches or binds: it inherits Modality.relates with ops=[] so it only matches the pointed node itself (modality.py:76-78, node_address.py:87-97); go(Z) with unbound Z is a vacuous success that leaves the pointer in place (verified). The bundled anticipation-res rule using <Z>+Q / go(Z) is therefore inert-but-harmless in this port.
- Unbound-vs-unbound metavariable comparison is FALSE (MetaType.__eq__ -> self._meta == other_value(None) -> False, meta_stub.py:51-53 + element.py:73-74), so a stored requirement ?<\/0>Ty(Y) can never be re-matched by the same trigger text in a later rule — the classic two-step Introduction/Prediction schema does not work.
- An unconstrained schematic trigger like ?ty(X) causes combinatorial explosion in _apply_all_permutations' optional-grammar expansion; the only guard is _MAX_LEXICAL_ADJUSTMENT_PAIRS = 50,000 tree pairs (interactive_context_parser.py:62,441-447), which in practice looks like a multi-minute hang.
- IfThenElse.from_lines and _find_end_of_embedded_ite detect nested blocks by SUBSTRING search for 'if'/'else' anywhere in a line (if_then_else.py:36-42, 163, 179) — an effect/formula argument containing the letters 'if' or 'else' (e.g. a predicate named 'shift' is safe only because find('if') is used on THEN/ELSE payload lines: 'shift' CONTAINS 'if' and WOULD be misparsed as a nested ITE). Avoid tokens containing 'if'/'else' in grammar files.
- get_if_indices splits a lexical action into multiple top-level IF segments on any line that STARTS with 'if' after strip (effect_factory.py:152-155); nested IFs in bundled grammars survive only because they are written on the same line as THEN/ELSE (e.g. 'ELSE\tIF ...'). A nested IF placed on its own line would be wrongly promoted to a new top-level segment.
- IfThenElse with an EMPTY chosen branch returns None (action fails) — not the unchanged tree (if_then_else.py:236-237); this is deliberate Java parity.
- The metavariable letter ranges differ by position: type metavars in ty() are [V-Z][0-9]* (dstype.py:18); bare label metavars are [V-Z][0-9]* or META (labels.py:27); freshput formula metavars are only S,T,U (fresh_put.py regex '([S-U])'); macro/template header params are any [A-Z][A-Z0-9]* (effect_factory.py:33); modality metavars are [A-Z][A-Z0-9]* (modality.py:21-31). A,B,C 'formula metavariables' mentioned in grammar-file comments parse via Formula.create, not MetaType.
- In macro headers, if ANY argument is not uppercase-alphanumeric the ENTIRE line including parentheses becomes the macro name with zero params (effect_factory.py:23-36) — that is how event_restrictor(past)/(pres)/(future) work: they are three distinct zero-arg macros matched verbatim by name at expansion (effect_factory.py:132-135).
- Lexicon.lookup/get truncate to top_n entries (default 3) (lexicon.py:362-372) — a word with >3 templates in lexicon.txt silently loses candidates at parse time even though all loaded.
- The sandbox: repo is READ-ONLY for this task; scratch grammars were written under $TMPDIR/ds-scratch (gramA/B/C/D variants) — reproduce experiments from there, and note full-lexicon parser construction plus first parse takes minutes; trim lexicon.txt to the needed words for quick experiments.
- speech-act-inference-grammar.txt is recognised but NEVER parsed ('rules not loaded in v0', speech_act_inference_grammar.py:21-23), so infer-sa is a no-op-ish effect and everything in that file is dead in the Python port.
- The '+' prefix (backtrack_on_success) is parsed (grammar.py:68-70) but consumed only by the induction/EM-learner modules (hypothesiser.py:362,383; ttr_hypothesiser.py:368,430), not by the interactive parser; exec_exhaustively similarly is induction-only.

## Answers

### q1
Best chokepoints, in order of leverage: (1) `Lexicon.__init__` (src/dylan/action/lexicon.py:182-249) is the single best place for lexicon-side validation — it is the only spot that simultaneously holds the parsed templates (`self._templates`, filled by `_init_lexical_templates`, lexicon.py:454-490), the macro results (`EffectFactory.init_macro_templates`, effect_factory.py:66-105), and the cleaned lexicon rows before `_read_words` (lexicon.py:492-541) consumes them; it already aggregates counters into the frozen `LexiconLoadStats` dataclass (lexicon.py:152-169) at lines 241-249, so validation results have a natural home. `_read_words` ALREADY detects rows referencing nonexistent templates (lexicon.py:510-514 — but only `logger.debug`, easily missed) and arity mismatches between lexicon columns and template parameters (lexicon.py:516-527, `lt.metavar_count != len(metavals)` → `logger.warning` + skip). (2) For duplicate computational-rule names: `Grammar._commit` (src/dylan/action/grammar.py:80-89) — `self[name] = action` on line 88 silently overwrites duplicates because `Grammar` subclasses `dict` (grammar.py:18); a `if name in self: raise/warn` there is the minimal fix. Duplicate lexical templates likewise silently overwrite at lexicon.py:467 and 487, and duplicate macros at effect_factory.py:91 and 100. (3) For cross-file validation with everything in hand (e.g. lexicon rows vs templates vs macros vs computational rules), the loader seam is `DAGParser.__init__`/`from_resource_dir` (src/dylan/parser/dag_parser.py:32-45, 58-62) or `InteractiveContextParser._apply_resource_dir` (src/dylan/parser/interactive_context_parser.py:234-253) — both construct `Lexicon(path)` and `Grammar(path)` together; a `validate()` call added there covers every load path including `set_grammar` (icp:255-261). How errors surface today: nothing raises except a malformed template header (`ValueError` at lexicon.py:477) and missing learnt-lexicon file (`FileNotFoundError`, lexicon.py:273-277). Everything else is stdlib-`logging` warnings/debug plus silent skip counters: missing computational-actions.txt → `logger.error` and an EMPTY grammar the parser happily runs with (grammar.py:36-38); unknown template → debug + `words_failed` counter; arity mismatch → warning + counter; unparsable effect lines → silent no-op `GenericEffect` (effect_factory.py:39-53, 263); unparsable IF labels → `GenericLabel` whose `check()` always returns False (labels.py:570-590, 735); macro arity mismatch at expansion → `None` → falls through to `GenericEffect` (effect_factory.py:141-150). ### q4
The interpreter loop is `IfThenElse.exec_tuple_context` (src/dylan/action/atomic/if_then_else.py:206-246). Setup: at embedding level 0 it calls `reset_all_meta_bindings()` (clears EVERY pooled metavariable — a documented divergence from Java's `resetBoundMetas`, comment lines 218-220) and rebuilds a `Backtracker` registering each IF-label's metas with the step index where they are introduced (199-204, 59-66); nested ITEs (embedding_level>0) reset only the shared existential 'bound meta' cells (221, element.py:92-96). Main loop (bounded at 64 attempts, line 225): check each IF label in order from `backtracker.index` via `label.check_with_tuple_as_context(tree, context)` (229-234). POINTER/TREE INTERACTION: the default check reads `tree.pointed_node` (labels.py:103-105) — triggers are evaluated at the current pointer; `ModalLabel.check_with_tuple_as_context` (labels.py:516-529) iterates ALL tree addresses, filters by `modality.relates(pointer, addr)`, and TEMPORARILY SETS `tree.pointer = addr` to check inner labels, restoring the saved pointer in a finally block — so modal triggers like `<\/1>ty(Y>X)` work by transient repointing; label equality itself is side-effecting (MetaElement binding). Branch selection: all IF labels pass → THEN effects, any failure → ELSE effects (235). An EMPTY selected branch returns None = action fails (236-237, Java parity per docstring 209-213). Branch effects run sequentially, mutating the same tree (238-242) — callers are responsible for cloning first (`DAGParser.apply_actions` dag_parser.py:98, `adjust_with_non_optional_grammar`:116, `complete_once`:141, `_apply_all_permutations` icp:412/418/454). ABORT PROPAGATION: `Abort.exec_tuple_context` returns None (abort.py); any None from an effect breaks the branch loop (241-242), then `Backtracker.can_backtrack_tuple_context` (79-101) tries to unbind the most recent backtrackable meta (recording tried values so they are not retried, element.py:54-61), re-checks that IF label, resets later metas, and reruns from that step; when backtracking is exhausted the whole ITE returns None (245-246). None then propagates: `Action.exec` → caller (action.py:36-40); `LexicalAction.exec` runs its multiple top-level IF segments in sequence and short-circuits on the first None (lexical_action.py:68-76); in the parser a None simply means the action is inapplicable — no DAG edge is added (icp:420-422, 454-455; dag_parser.py:117-118) — and word-level dead-ends are handled by DAG backtracking in `_adjust_once` (`dag.go_first()` / `dag.attempt_backtrack()`, icp:358-365) and ultimately `parse_word`'s reset-to-last-word + optional repair path (icp:583-592). Effects that can themselves veto: go (unreachable address, go.py), make (BottomLabel and non-link op, make.py), merge (fixedness conditions, merge.py), gofirst (no matching ancestor), copy_content (target missing/untyped), conjoin (no Fo and non-TTR argument).
