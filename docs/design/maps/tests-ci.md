## Answers

### q1
Model the module on tests/formula/test_ttr_record_type.py:112-151 (tuple-first @pytest.mark.parametrize with a leading `name`/id column) combined with the grammar-skip guard used in tests/test_parser_minimal_integration.py:16-17,56-57. Concretely: (1) module docstring + `from __future__ import annotations`; (2) module constant `GRAMMAR = Path(__file__).resolve().parents[1] / "resources" / "<grammar-dir>"`; (3) a guard `if not (GRAMMAR / "lexicon.txt").is_file(): pytest.skip("<grammar> not in resources")` at the top of the test body (that is the existing house pattern; a module-level `pytestmark = pytest.mark.skipif(...)` would also work but is not used anywhere yet); (4) `@pytest.mark.parametrize(("name", "sentence", "expected_substrings"), [ pytest.param("kem-1", "john upset mary", ["subj(", "upset"], marks=pytest.mark.xfail(reason="lexicon lacks 'upset'", strict=False)), ... ])`; (5) inside the test build a fresh `InteractiveContextParser(GRAMMAR)`, `p.init()`, loop `p.parse_word(UtteredWord(w, "Dylan", "you"))` per whitespace token (or use `ds.parse(sentence, "<grammar-id>")` like tests/test_dynamicsyntax_parse.py:37), then assert substrings against `str(tup.get_semantics(p.context))`, using the whitespace-compaction idiom `s.replace(" ", "")` from tests/test_parser_minimal_integration.py:75-77 so assertions are robust to spacing. Note: xfail is currently unused in this repo (only pytest.skip / skipif / mark.timeout / mark.skip appear — see grep results), so xfail-marked params are new but idiomatic pytest; use strict=False so cases that start passing don't fail CI, or strict=True if you want promotion pressure. Keep each expected-substring list minimal (like "man(" / "arrive" in test_dynamicsyntax_parse.py:41) rather than full record types, because fresh-variable numbering is unstable. New module must pass `ruff check tests` (F401 unused imports are the usual trap).
