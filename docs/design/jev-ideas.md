# Ideas for using Jev in DynamicSyntax

Scope: the DynamicSyntax repo only (`/Users/graogro/Dropbox/revisiting-formal-semantics/DynamicSyntax`, branch `constructive-ds`). Nothing here depends on the atlas. Jev (TypeSafe) is used as a typed decision model: state plus atomic questions, answers as probability distributions, never text, never a licenser, never a verifier. Every idea keeps the DS engine (IF triggers, GATES, PCC put clash, case filters, coqc) and the sourced thesis judgments as the only authorities. Where an idea below would let a Jev answer change what the engine builds or reports, it is marked as needing an explicit exception in section 6 and ships log-only until that exception is granted.

Ranking method: three panels produced 18 ideas; two judges scored each (grammar-safety, value, simplicity, feasibility, 40 max each). Scores below are the sum of both judges. Ideas both judges marked keep=false are dropped, with a reason each: 0.4 Greek fragment acquisition (the Greek lexicons are generated from `LEXICA` in `scripts/build_greek_fragments.py:12-40`, shipped grammar files are off limits, `lexical_expansion.py:22` admits English grammars only, and no Greek accuracy figure exists); 1.5 unfixed-node merge (`Tree.merge_unfixed` never merges, `docs/design/maps/tree-internals.md:66`, and the decision only affects `2015-english-ttr`); 1.6 default reading and scope, 2.3 workbench estimate panel and 2.6 diagnostics triage (all three put a model answer where the docs put the engine or the human, section 3). Ideas 1.3 and 0.5 are the same decision and are presented merged; whether to keep them merged is decision 18. All rankings and schedules in this document are proposals for Stergios, not settled decisions.

### 1. Lexical-entry prior at lookup, left context only (merged 1.3 and 0.5), score 68 and 62

Decision: when `Lexicon.lookup(word)` returns more than one `LexicalAction`, one Choice "Which lexical entry of the next word fits the sentence so far" over options `e0..eN` plus `other_or_none`. Each option's prose is generated in code from the actual lexicon row (form, template, params) plus a fixed one-line description per template, never typed by hand. Example from `src/dynamicsyntax/grammars/2026-smg-mltt/lexicon.txt`: `ξέρω finite-plain know speaker`, `ξέρω finite-neg know speaker`, `ξέρω finite-na know speaker` become "finite-plain: plain finite form, predicate know, subject speaker", "finite-neg: negated finite form after δεν/εν/κι, predicate know, subject speaker", "finite-na: finite form after να, predicate know, subject speaker" (`pro` is the subject only for `αγαπά` and `γράφει`). 2015 TTR: `v_tran_fin arrest`, `v_intran_fin arrest`. One Choice, not one Noul per entry (cross-question invariants are not guaranteed).

State: `{"grammar", "tokens_so_far", "next_word", "remaining_tokens", "entries": [{"id", "template", "params", "row"}]}`, under 600 chars, no tree. Chunk id = sha256 of the JSON. Cache and recorded answers keyed by `(chunk_id, question_set_hash, model)` exactly as section 4, so rewording `entry_v1` to `entry_v2` or changing the model never reuses a stale answer.

Hook (only after the go/no-go of the first action in section 5): `interactive_context_parser.py:422` (`all_actions = self.lexicon.lookup(word.word)`); after lookup, if more than one action and the client is on, get priors; `_add_permutation_child` (:494-526) sets `edge.prior` on the word edge it creates. Comparator: replace the bare `return 1` at `word_level_context_dag.py:115` with a prior comparison when both priors are set, so the completeness heuristic keeps precedence and Jev only breaks ties. Scope the hook to the parser call: `Lexicon.lookup` is also called by `greek_workbench.assessment` (:283, clitic count) and by lexical-expansion checks, so a ranker attached to `Lexicon` itself would fire there too. Separate engine decision (decision 5): lift or raise `top_n=3` (`lexicon.py:185, 373`) so the 48 TTR forms with more than three entries are all built; a prior cannot rank what is never built.

Threshold and cost: tie-break only, nothing is dropped. One threshold on `p(top)`, not on `confidence`, because the vendor confidence statistic depends on option count (4 options for a Greek verb, up to 7 for a TTR verb) and one confidence number is not one probability. Placeholder `t_prior = 0.50` on `p(top)`; below it, file order as today. The calibration report gives the confidence value equivalent to `p(top) = 0.50` per option count for reference. Cost of a wrong answer is one extra dead-end traversal. One call per ambiguous word, about 150 tokens, 100 to 500 ms.

What it buys: the Greek go/no-go in one afternoon. In the Greek fragments the correct verb entry is fully determined by whether δεν/εν/κι or να precedes (`LEXICA` and `GATES` in `build_greek_fragments.py`), so if Jev cannot pick `finite-neg` after δεν from a 20-token state, per-word Greek use is out. This is a script-robustness check (Greek script vs ASCII alias), not a Greek accuracy figure, because the cases are trivially predictable; report Greek verbs separately from the 2015 TTR verbs (`arrest`, `know`, `begin`, up to 6 rows) where context really decides. Also makes the "Best-first" docstring (`interactive_context_parser.py:73`) partly true at the lexical fan-out.

Calibration: replay with `dynamicsyntax.parse(trace=True)` (`src/dynamicsyntax/_parse.py:185-283`); for each ambiguous word on a successful parse the label is the `LexicalAction` on the winning edge. Sources: the 10 licensed `CASES` in Greek and ASCII (20 strings but only 16 distinct surface forms, since smg-imp/cg-imp and smg-na/cg-na share text; deduplicate and report as 16), the 8 workbench sentences (`workbench_api.py:61-72`) and 5 expansion sentences on grammars where multi-entry words occur. The BabyDS-plus-robot-grammar calibration proposed in 0.5 is unverified: `Tree.merge_unfixed` never merges (`maps/tree-internals.md:66`) and the robot grammar uses `star-adjunction`/`merge`, so the gold-path labelling there may not exist. Metrics: top-1 agreement, `p(top)` at hits vs misses, Greek vs ASCII, DAG tuples visited with and without priors. Proposed reading rule (decision 7): Greek per-word use is worth pursuing only if agreement is at least 15/16 on the distinct Greek items with `p(top) > 0.7`; otherwise Jev is restricted to English states.

Effort: S. The first session is the zero-edit scratch measurement of section 5; only after it: prior attribute on `GroundableEdge` (`src/dylan/dag/groundable_edge.py:8`), the hook at :422, the tie-break at :115, `questions/entry_v1.py`, dry-run stub, replay.

### 2. Ranked fan-out and the shared decision infrastructure (1.1), score 63

Decision: at every word where `_apply_all_permutations` built more than one child, one Choice "Which candidate partial tree continues the sentence so far toward a complete parse of the whole token list", options `c0..cN` (one per child edge, at most 255) plus `none_of_these`. Measured 0.8k to 2k chars per candidate; 2 to 4 candidates gives 3k to 8k chars. Chunk id = sha256 of canonical JSON; per-candidate key reuses the `complete_tree` state key format (`dag_parser.py:177-183`).

Hooks (three, small): (1) `GroundableEdge.prior: float | None` (`groundable_edge.py:8`); (2) `WordLevelContextDAG.rank_hook`, called from `get_out_edges` (:117-121) once per parent when `len(raw) > 1` and no prior is set (idempotent, since `get_out_edges` is re-sorted on every `go_first` and `attempt_backtrack`); the comparator compares priors before the incompleteness measure at :100-105 only when both are set; (3) new package `src/dylan/decision/` (`state.py`, `client.py`, `log.py`, `questions/fanout_v1.py`). `go_first` (:354-376) and `attempt_backtrack` (:335-352) untouched; every child is still built and traversed when needed. Workbench: field `decision_mode` in `{off, stub, jev}` validated next to `lexical_mode` in `validate_request` (`workbench_api.py:84-107`, which delegates to `lexical_expansion.validate_options` at :143-144), advertised by `configuration()` (`workbench_api.py:26-83`) as a new `decision` block (`modes`, `model`, `grammars`) beside the existing `lexical` block at :79, and read by `workbench/app.js` the way `lexical_mode` is (payload at `app.js:123`, gating at `:612-624`); without the config block and the select the workbench cannot choose a mode. The stub must return equal priors so the comparator falls through and the 546-test suite stays byte-identical.

Threshold and cost: ordering only; one threshold `t_order = 0.50` on `p(top)`; below it, comparator order and log. Pruning is off limits in v1. Latency: one call per multi-child fan-out; a 6-token mltt sentence (56 ms today) gains 0.3 to 1.5 s; the 30 s worker deadline (`workbench_server.py:81, 121`) is safe. Cost under 0.01 cent per call.

What it buys: the shared client, stub, JSONL log, serializer and replay script that every other idea reuses; fewer dead-end traversals per word for the three-way Greek verbs and for the thesis grammar to come; "search instrumentation" is item 4 of the next-work list in `docs/design/lexical-expansion.md:153-176`. Calibration: replay all successfully parsed test sentences (roughly 50 to 60: `workbench_api.py:18-23, 61-72`, `test_native_semantics.py:53-62, 111-119`, `test_clause_embedding.py:33-40`, licensed `CASES`, 7 dialogue presets, 5 expansion sentences); at each fan-out the winning-path child (`_active_path_edges`, `_parse.py:24-37`) is the label. Metrics: Jev top-1 vs comparator top-1, MRR, successful `attempt_backtrack` calls per sentence, flat-distribution rate (max prob < 0.4), Greek vs ASCII. Proposed reading rule: on by default only if Jev beats the comparator by at least 10 points on at least 30 labelled fan-outs with the suite byte-identical under stub and recorded answers.

Effort: M; the nodes-only snapshot and a DAG serializer (tuple ids, edge kind, word, action names, seen flags), which do not exist, are the real first-week work, not the three hooks. Threshold and cost: none in v1 (no action). ## 3. Off limits

- Jev as a grammaticality judge: no Jev output sets `judgment.status`, `failure.kind`, `ok`, `complete` or any test assertion. `greek_workbench.py:3-4`, `greek-clitics.md:63-83` and `lexical-expansion.md:145-147` make the engine and sourced judgments the only verdicts; model output is a separate column labelled as an estimate. This is why 1.6, 2.3, 2.6 and the `constraint_violation` option of 1.2 are out, and why idea 5's `licensed` Noul needs decision 20.
- Jev as licenser, pruner or verifier: which children exist (lookup, optional-rule BFS, star fixpoint, IF checks, PCC put clash, case filters, type checking, coqc) and which proposals reach the validator is engine business; Jev orders only. No beam mode in v1. The hold of idea 4, the drop of idea 7 and the sole-proposer mode of idea 6 all breach this and are gated on decision 19.
- Jev generating text: lemma, symbol, evidence, Greek transliteration, PRED names, LOFT triggers, DS action programs, formulas, Coq, LaTeX. `Lexicon.instantiate_template` (`lexicon.py:390-393`) does not interpret arbitrary programs; only enumerated options reach it.
- Jev in the test suite live: probabilities drift 0 to 2.2 percent between identical passes, so pytest runs with the stub or a recorded-answer cache; a test depending on a live answer is broken.
- Counting or arithmetic: clitic count, open requirements, incompleteness measure, positions, repetition are computed in code (`tree.py:638-647`, `greek_workbench.py:283-285`) and sent as fields, never asked, not even as logged-only Scores.
- Referent resolution and presupposition solving (`loft-engine-status.md:21-26`); Jev may rank candidates once a solver enumerates them.
- Answer leakage: `CASES[i]["explanation"]`, `DIALECTS[d]["explanation"]`, gloss text stating the rule, or test assertion text is never sent when the label measured is placement or acceptability; idea 5 condition B sends the dialect explanation on purpose and is therefore reported only as a rule-following test.
- Writing to shipped grammar files, `LEXICA`, `GATES`, `lexicon.txt`, `PROTECTED` or `CASES`; model output stays in the session, the cache and the log.
- The induction EM learner (`src/dylan/induction/em_learner/word_hypothesis_base.py:92-154`) is a separate learner and untouched.
- Semantic judgments on readings or scope (`mltt/semantics.py:138-151`), even as display defaults.
- Person, case, number and gender questions for Greek clitics until a `clitic(REF,PERSON,CASE)` template exists; today nothing consumes them.

## 4. Shared infrastructure

Layout inside the DS repo, one package used by every idea:

```
src/dylan/decision/
  __init__.py
  client.py      decide(state, questions, *, chunk_id, idea) -> answers, writes one log record
  state.py       nodes_only_snapshot(tree), fanout_state(...), entry_state(...)
  log.py         append_jsonl(record)
  questions/
    entry_v1.py, fanout_v1.py, lexical_gate_v1.py, cases_v1.py, corpus_v1.py, triage_v1.py, closed_v1_sentence.py, closed_v1_word.py, ttr_v1.py
scripts/
  jev_probe_entries.py (zero-edit first measurement), replay_fanout.py, jev_calibrate_cases.py, build_clitic_corpus.py, triage_corpus.py, jev_ttr_harness.py
```

Client: mode from `DS_DECISION_MODEL` in `{off, stub, jev-1.13.0}`, default `stub`. Either `typesafe_sdk.TypeSafeClient(model="jev-1.13.0").system_one(state, questions)` (signature verified: `system_one(state, questions, *, model=None, retry=None, timeout=None, ...) -> SystemOneResponse` with `.model`, `.usage`, `.answers`) as an optional dependency group, or a urllib `POST https://api.typesafe.ai/v1/systemone` with `Authorization: Bearer` following the conventions of `src/dylan/lexical_provider.py` (HTTPS or loopback, 15 s timeout, redacted errors). Key from `TYPESAFE_API_KEY` only, never in the repo or the cache key.

Dry-run stub: records the state and question set to the log, returns uniform probabilities and confidence 0 for Choice, uniform over levels for Score, 0.5 for Noul. Ordering hooks must treat equal priors as "fall through to existing behaviour" so the suite is byte-identical under the stub. One test per hook asserts this.

Logging schema, one JSONL line per call, default `.ds-workbench/jev.jsonl` (env `DS_JEV_LOG`), written by `decide()` itself so no idea can skip it: `{ts, model (from the response, not the request), question_set_hash (sha256 of serialized questions including option and criteria prose), chunk_id, idea, grammar, sentence_id, word_index, candidate_ids, answers: {name: {choice|score|noul, probabilities, confidence}}, action_taken, deterministic_order, latency_ms, stub: bool, input_tokens}`. Idea 3's `model_labels` embeds this record; ideas 7 and 8 derive their tables from it.

Question-set versioning: each `questions/*_vN.py` module is frozen once used live; rewording creates `vN+1`; the hash in the log is what ties a threshold to a wording. Thresholds are stored next to the version, never as globals, and every threshold is on `p(top)` or a Noul value, not on the vendor confidence statistic. Recorded answers for tests and every cache are keyed by `(chunk_id, question_set_hash, model)`.

State discipline (from the jaggedness page): send only fields the question needs; no whole workbench results (120k to 557k chars measured); nodes-only trees; all numeric facts precomputed in code; every Choice carries an `other` or `not_stated` option; every Noul phrased so high means yes; no double negatives; option prose generated from repo rows, not typed.
